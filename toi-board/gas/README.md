# といボード GAS版

学年で1つのスプレッドシートを持ちます。児童と先生は同じURLを開き、Googleアカウントで画面が分かれます。授業中はずっと開いたままにする前提です。

## 0. 先にドメインを確かめる（5分）
`whoami/Code.gs` を新しいApps Scriptに貼ります。下の「3」と同じ設定で公開し、児童アカウントで開いてください。
- 児童のメールが出る → このまま進められます。
- 空 → 本番も児童を判定できません。番号を入力する方式に変える必要があるので、相談してください。
- 開けない → 公開範囲（アクセスできるユーザー）に児童のドメインが入っていません。

## 1. スプレッドシートを作る
1. 新しいスプレッドシートを作り、拡張機能 → Apps Script を開きます。
2. `Code.gs` を貼ります。HTMLファイルを `Index` と `Trial` という名前で作り、`Index.html` と `Trial.html` の中身を貼ります。
   - **3つとも同じコミットのものを貼ってください**（一部だけ貼り直さない）。
   - `Trial` は体験版です。先生画面の「体験する」から `?trial=1` で開きます。見本のデータはブラウザの中だけにあり、本番のシートには書きません。
3. `setup` を実行します。シートが7枚できます（名簿・先生・スポット・items・stars・comments・modes）。**何度実行しても、入っているデータと版は消えません**（足りないシートを足すだけ）。
4. **シートを保護します**（データ → シートと範囲を保護 → items・stars・comments・modes を「自分のみ」）。手で並べ替え・行の削除をすると、付箋が壊れます。

## 2. 表を埋める
| シート | 書くこと |
|---|---|
| 名簿 | メール／組（A・B・C）／班（1〜7）／番号 |
| 先生 | メール／最初に開く組。`@edu.nishi.or.jp` の人は、書かなくても先生として開けます |
| スポット | 組／班／スポット名（入れ替え後の一覧） |

名簿・スポットを直したら、`clearWhoCache` を実行してください（覚えを消します）。

## 3. 公開
デプロイ → 新しいデプロイ → ウェブアプリで公開します。
- 次のユーザーとして実行：**自分**
- アクセスできるユーザー：**（学校の）ドメイン内の全員**

ファイルを直したら、「デプロイを管理」→ 編集 →「新しいバージョン」で更新します。保存しただけでは、/exec のURLに反映されません。

## しくみ（約90人が同時に使う前提）
- **モード・回**：組ごとに決めます。決めた組の児童ができることだけが変わります。
  - 変えると、児童の画面に**10秒ほどで届きます**（ページの更新はいりません）。全員が一斉に開き直すと、同時に動かせる処理の上限（約30）を超えるためです。
  - 届く前に許されない操作をすると、サーバーがはね、画面は最新の状態を取り直します。
- **読む**：児童は約10秒（±3秒）ごとに、自分の班（＋今見ている班、シール貼りの時はその班たち）とモードの版だけを確かめます。
  - 版はキャッシュからまとめて引くので、変化がなければシートは読みません。
  - タブが裏に回っている間は確かめません。先生画面は学年全体の版を確かめます。
- **書く**：付箋は0.25秒、シール・コメントは1.5秒ためて、まとめて送ります。画面を離れる時は、ためている分をすぐ送ります。
  - **すでにある付箋は、変わった項目だけ**（文・位置・重なり など）を送り、サーバーは今の付箋に重ねます。同じ班の子が同時に別の項目を変えても、どちらも消えません（同じ項目を同時に変えた時だけ、後の人が優先）。
  - もとに戻す（Ctrl+Z）も、自分が変えた項目だけを戻します。
  - 送り終わるまでの変更は端末にも置き、通信が切れたまま閉じても、次に開いた時に送り直します。
  - 児童の「消す」は行を残して印を付けるだけです（同じ班ならやり直しで戻せる）。**先生の「完全に消す」**だけが中身を消します（もどせません）。
  - シールだけの書き込みでは、付箋のシートを読みません（付箋がどの班かはキャッシュで引きます）。
  - サーバーは、自分の班の物以外への書き込み・消去や、児童によるモード変更をはねます。最後に書いた人を優先します。
- **整理役**：位置・重なり・枠の新規と削除は、その班の整理役（先着1人・時間は授業の設定で組ごとに3/5/10/15分、既定5分・キャッシュに保持）の書き込みだけを受け付けます。整理役がいなければ誰も動かせません。先生は班のボードで指定・解除できます。
- **見合い会の順番**：modes の rot に {min, start, paused} を持ち、時刻はサーバーが決めます。今の班以外へのシール・コメントと、今の班の児童からの書き込みははねます。児童は確認のたびに「開いている」をキャッシュに残し（2分）、先生画面に人数が出ます。
- **混雑した時**：開く・確かめる・書くのに失敗したら、1〜5秒のばらばらな間をおいて自動でやり直します（一斉のやり直しを防ぐ）。
- **見えるもの**：児童に届くのは、自分の班の全部と、許された範囲の他班の表がわ・いただきもの・見てほしい付箋だけです。
  - 書いた人・シールを貼った人は先生にしか分かりません。シールの数は自分の班にだけ届きます。
- **検索**：端末の中のデータを探すだけなので、サーバーの負荷は増えません。
- **名簿・先生・スポットを直したとき**：`clearWhoCache` を実行します。
- **版の確認**：画面とサーバーの版（`API_WANT`／`API_VER`）が食い違うと、画面に警告が出ます。

## 実機で確かめること（模擬では分からない）
- 同時に使ったときの遅延とエラー。まず1クラス30人でシール貼りを5分行い、「つながりにくい」の表示回数と、シールが班のボードに出るまでの秒数を数えます。
- 4GB機での動作の重さ。
