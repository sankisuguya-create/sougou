# といボード GAS版

学年で1つのスプレッドシートを持ちます。児童と先生は同じURLを開き、Googleアカウントで画面が分かれます。授業中はずっと開いたままにする前提です。

## 0. 先にドメインを確かめる（5分）
`whoami/Code.gs` を新しいApps Scriptに貼ります。下の「3」と同じ設定で公開し、児童アカウントで開いてください。
- 児童のメールが出る → このまま進められます。
- 空 → 本番も児童を判定できません。番号を入力する方式に変える必要があるので、相談してください。
- 開けない → 公開範囲（アクセスできるユーザー）に児童のドメインが入っていません。

## 1. スプレッドシートを作る
1. 新しいスプレッドシートを作り、拡張機能 → Apps Script を開きます。
2. `Code.gs` を貼ります。HTMLファイルを `Index` という名前で作り、`Index.html` の中身を貼ります。
   - **2つとも同じコミットのものを貼ってください**（片方だけ貼り直さない）。
3. `setup` を1回実行します。シートが6枚できます。

## 2. 表を埋める
| シート | 書くこと |
|---|---|
| 名簿 | メール／組（A・B・C）／班（1〜7）／番号 |
| 先生 | メール／最初に開く組。`@edu.nishi.or.jp` の人は、書かなくても先生として開けます |
| スポット | 組／班／スポット名（入れ替え後の一覧） |

名簿・スポットを直したら、`clearWhoCache` を実行してください（覚えを消します）。

## 3. 公開
デプロイ → 新しいデプロイ → ウェブアプリで公開します。
- 次のユーザーとして実行：**自分**
- アクセスできるユーザー：**（学校の）ドメイン内の全員**

ファイルを直したら、「デプロイを管理」→ 編集 →「新しいバージョン」で更新します。保存しただけでは、/exec のURLに反映されません。

## しくみ（軽さを優先）
- **モード**：組ごとに決めます。決めた組の児童ができることだけが変わります。
  - 児童の画面がモードを読むのは、ページを開いた時の1回だけです。
  - **モードを変えたら「ページを更新して」と合図してください**。先生画面にも、そう表示されます。
  - 更新するまでは前のモードの画面のままです。その間に許されない操作をすると、サーバーがはね、画面に「ページを更新してね」と出ます。
- **読む**：児童は約10秒（±3秒）ごとに、自分の班の版を確かめます。ほかの班を開いている間は、その班の版も確かめます。
  - 変化がなければ、サーバーはシートを読まずに返します。
  - ほかの班の書き込みでは、自分の班のシートの読み直しは起きません。
  - ほかの班の中身は、開いた時に初めて取りに行きます。
  - タブが裏に回っている間は確かめません。先生画面は学年全体の版を確かめます。
- **書く**：変更は付箋1枚単位でまとめて送ります（0.25秒ためる）。最後に書いた人を優先します。サーバーは、自分の班の物以外への書き込み・消去や、児童によるモード変更をはねます。
- **見えるもの**：児童に届くのは、自分の班の全部と、許された範囲の他班の表がわ・いただきものだけです。
  - 書いた人は先生にしか届きません。
  - シールの数は自分の班にだけ届き、貼った人は記号に置き換えます。
- **シール（班の外）**：入れると、その組の児童の画面がシール貼り画面になります。
  - 範囲の中のほかの班の「見てほしい付箋」は、開いた時に1回だけ取りに行きます。新しく「見てほしい」にした付箋を出すには、更新の合図が要ります。
  - 貼った場所は本人にだけ届きます。
- **検索**：端末の中のデータを探すだけなので、サーバーの負荷は増えません。児童は自分の班の付箋だけ、先生は学年全体を探せます。
- **名簿・先生・スポットを直したとき**：`clearWhoCache` を実行します。
- **版の確認**：画面とサーバーの版（`API_WANT`／`API_VER`）が食い違うと、画面に警告が出ます。

## 実機で確かめること（模擬では分からない）
- 87台を同時に開いたときの遅延と、同時実行の上限によるエラー。まず1班、次に1クラスで測ります。
- 4GB機での動作の重さ。
